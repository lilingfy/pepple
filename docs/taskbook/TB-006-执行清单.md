# TB-006 后端 BFF 与接口技术预研执行清单

> 适用对象：后端实现、测试、文档同步

## 1. 执行目标

把 `TB-006` 拆成可直接执行的子任务，确保后端 BFF、`practice`、翻译器和陪练场契约能够按照第二版前端 HTML 落地，并且保持 TDD、可验证、可回归。

## 2. 执行原则

1. 先补测试，再写实现。
2. 先定义 DTO，再写路由。
3. 先做通用基础设施，再做业务接口。
4. `practice` 是唯一命名，不引入 `practice-book`。
5. 所有接口必须有 fallback 和错误边界。
6. 任何数据库字段都只存最小必要数据。

## 3. 子任务拆解

### 子任务 1: 后端契约和类型基座

**目标**
- 建立所有接口共用的 request / response DTO
- 给后续路由、服务、测试提供统一类型来源

**建议文件**
- 新增 `packages/types/src/backend.ts`
- 修改 `packages/types/src/index.ts`
- 必要时更新 `tsconfig` 或导出入口

**交付物**
- `DecodeRequest` / `DecodeResponse`
- `SimulatorRequest` / `SimulatorResponse`
- `PracticeCreateRequest` / `PracticeListResponse`
- `BackendErrorResponse`
- `ScenarioItem`
- `SessionSnapshot`

**验收点**
- 类型能被后续 route 和 service 直接引用
- 不存在重复定义的接口字段

---

### 子任务 2: 通用后端基础设施

**目标**
- 把输入校验、错误体、超时、限流、匿名会话、PII 脱敏封装成公共能力

**建议文件**
- 新增 `apps/web/lib/backend/policy/*`
- 新增 `apps/web/lib/backend/http/*`
- 新增 `apps/web/lib/backend/errors/*`
- 新增 `apps/web/lib/backend/sessions/*`

**交付物**
- `validateWithSchema`
- `createBackendError`
- `withTimeout`
- `ensureGuestSession`
- `redactSensitiveText`
- `normalizeApiFailure`

**验收点**
- 路由里不再直接散写脱敏逻辑
- 任一上游异常都能转换成稳定错误体

---

### 子任务 3: 读心翻译器后端

**目标**
- 完成 `POST /api/decode`
- 输出前端可见的固定字段
- 具备 deterministic fallback

**建议文件**
- 新增 `apps/web/lib/backend/decode/*`
- 修改 `apps/web/app/api/decode/route.ts`
- 新增 `apps/web/tests/backend/decode.test.ts`

**交付物**
- 文本输入校验
- PII 脱敏
- LLM provider 适配
- 本地 fallback 结果生成
- `analysis_logs` 落库

**验收点**
- 前端不需要改字段名就能显示结果
- LLM 不可用时仍有稳定响应

---

### 子任务 4: `practice` 后端

**目标**
- 完成练习条目的保存、查询、更新、删除
- 统一保存翻译器和陪练场的有价值内容

**建议文件**
- 新增 `apps/web/lib/backend/practice/*`
- 修改 `apps/web/app/api/practice/route.ts`
- 新增 `apps/web/app/api/practice/[practiceId]/route.ts`
- 新增 `apps/web/tests/backend/practice.test.ts`

**交付物**
- `POST /api/practice`
- `GET /api/practice`
- `PATCH /api/practice/[practiceId]`
- `DELETE /api/practice/[practiceId]`

**验收点**
- 翻译器保存时默认使用第一条回复建议作为 `primaryReply`
- 陪练场保存时 `primaryReply` 由调用方显式指定
- 练习条目支持收藏和归档状态

---

### 子任务 5: 模拟陪练场后端

**目标**
- 完成场景目录、会话流转、结束总结
- 对齐前端三栏布局对应的数据结构

**建议文件**
- 新增 `apps/web/lib/backend/simulator/*`
- 修改 `apps/web/app/api/scenarios/route.ts`
- 修改 `apps/web/app/api/simulator/route.ts`
- 新增 `apps/web/app/api/simulator/[sessionId]/end/route.ts`
- 新增 `apps/web/tests/backend/simulator.test.ts`

**交付物**
- `GET /api/scenarios`
- `POST /api/simulator`
- `POST /api/simulator/[sessionId]/end`
- `start / turn / restart` 会话语义
- `rightPanel` 固定字段输出

**验收点**
- 三个固定场景按稳定顺序返回
- 会话开始、续聊、重启、结束的状态一致
- 右侧面板字段和前端可见卡片一一对应

**验收点**

## 4. 推荐执行顺序

1. 子任务 1，先冻结类型。
2. 子任务 2，搭通用基础设施。
3. 子任务 7 的最小测试骨架，先让测试目录和配置就位。
4. 子任务 3，先落翻译器主链路。
5. 子任务 4，落 `practice`。
6. 子任务 5，落陪练场。
7. 子任务 6，补数据库迁移。
8. 子任务 8，同步文档和 OpenAPI。

## 5. 逐项完成标准

- 每个子任务都能独立提交。
- 每个子任务都有对应测试或可检查的输出。
- 完成顺序可以调整，但类型、测试、接口契约不能倒序失控。
