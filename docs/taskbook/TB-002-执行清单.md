# TB-002 读心翻译器技术预研执行清单

> 适用对象：翻译器前端实现、状态管理、接口接入与验收

## 1. 执行目标

把读心翻译器任务书拆成可直接执行的前端任务，确保页面能按第二版设计稿完成输入、解码、结果展示、回复建议交互以及 `practice` 保存入口。

## 2. 执行原则

1. 先定义前端页面状态和 DTO 映射，再写界面实现。
2. 输入区、结果区和动作区必须与后端契约解耦。
3. 页面必须兼容后端 fallback 响应。
4. 收藏入口统一使用 `practice` 命名。
5. 优先做稳定交互，再补视觉细节和动效。

## 3. 子任务拆解

### 子任务 1: 页面路由与状态骨架

**目标**
- 搭建翻译器页面路由、页面壳和基本状态
- 明确输入态、加载态、结果态、错误态

**建议文件**
- 修改 `apps/web/app/(main)/translator/page.tsx`
- 新增 `apps/web/components/translator/TranslatorPage.tsx`
- 新增 `apps/web/store/translator-store.ts`
- 新增 `apps/web/tests/frontend/translator-page.test.tsx`

**交付物**
- 页面壳
- 初始状态
- 错误与加载状态
- 优先复用 `PageShell` 与共享布局容器

**验收点**
- 页面能独立渲染四种核心状态

---

### 子任务 2: 输入区与工具栏

**目标**
- 实现文本输入、字符计数、语音/附件入口和情绪状态条

**建议文件**
- 新增 `apps/web/components/translator/InputArea.tsx`
- 新增 `apps/web/components/translator/EmotionStatusBar.tsx`

**交付物**
- 多行文本输入框
- 实时字符计数
- 工具栏按钮
- 情绪状态展示
- 输入容器优先复用 `PebbleInputShell`，状态展示优先复用 `StatusPill`

**验收点**
- 输入行为稳定
- 聚焦和空状态表现清晰

---

### 子任务 3: 解码按钮与请求流转

**目标**
- 实现解码按钮、请求触发、禁用态和 loading 动效
- 与 `POST /api/decode` 对接

**建议文件**
- 新增 `apps/web/components/translator/DecodeButton.tsx`
- 新增 `apps/web/lib/frontend/decode-client.ts`
- 修改翻译器页面容器组件

**交付物**
- 解码按钮
- 请求封装
- loading 和失败提示
- 主按钮优先复用 `PebbleButton`

**验收点**
- 重复点击不会发起并发污染请求
- 请求失败时用户能看到稳定反馈

---

### 子任务 4: 分析结果区

**目标**
- 渲染表面语义、潜台词、情绪状态和情绪分数
- 保证字段与后端响应一一对应

**建议文件**
- 新增 `apps/web/components/translator/AnalysisResult.tsx`
- 新增 `apps/web/components/translator/AnalysisCard.tsx`

**交付物**
- 表面语义卡片
- 潜台词卡片
- 情绪状态显示
- 空结果和错误结果处理
- 分析区优先复用 `GlassCard`

**验收点**
- 页面不依赖旧字段名
- fallback 响应也能正常渲染

---

### 子任务 5: 回复建议和 `practice` 入口

**目标**
- 展示 A/B/C 三条回复建议
- 支持复制和保存到 `practice`

**建议文件**
- 新增 `apps/web/components/translator/ReplySuggestions.tsx`
- 新增 `apps/web/components/translator/ReplySuggestionCard.tsx`
- 新增 `apps/web/lib/frontend/practice-client.ts`

**交付物**
- 三张建议卡片
- 复制交互
- `POST /api/practice` 保存入口

**验收点**
- 卡片顺序严格保持 A / B / C
- 保存时默认第一条建议作为 `primaryReply`

---

### 子任务 6: 响应式与视觉还原

**目标**
- 把桌面三栏布局和移动端堆叠布局打通
- 补齐设计稿中的鹅卵石形状、玻璃质感和微动效

**建议文件**
- 修改 `apps/web/components/translator/*`
- 必要时调整设计系统组件

**交付物**
- 桌面三栏布局
- 移动端堆叠布局
- 主要 hover / loading / reveal 动效

**验收点**
- 移动端可单手完成核心操作
- 不出现内容裁剪或布局错位

---

### 子任务 7: 测试与回归

**目标**
- 为翻译器页面建立稳定回归测试
- 锁定输入、请求、渲染和保存行为

**建议文件**
- 新增 `apps/web/tests/frontend/translator-page.test.tsx`
- 必要时新增 `apps/web/tests/e2e/translator.spec.ts`

**交付物**
- 输入与按钮测试
- 成功响应渲染测试
- 错误态和 fallback 测试
- `practice` 保存行为测试

**验收点**
- 前后端契约变更时能及时暴露回归问题

## 4. 推荐执行顺序

1. 子任务 1，先定页面状态。
2. 子任务 2，完成输入区。
3. 子任务 3，打通解码请求。
4. 子任务 4，接结果区。
5. 子任务 5，接回复建议和 `practice`。
6. 子任务 6，补响应式和视觉。
7. 子任务 7，补回归测试。

## 5. 逐项完成标准

- 页面状态清晰。
- 解码链路完整。
- 建议区和 `practice` 入口可用。
- 与后端契约保持一致。
