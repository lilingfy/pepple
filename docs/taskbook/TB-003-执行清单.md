# TB-003 模拟陪练场技术预研执行清单

> 适用对象：陪练场前端实现、会话交互、状态管理与验收

## 1. 执行目标

把模拟陪练场任务书拆成可直接执行的前端任务，确保页面可以完成场景切换、会话开始、消息往返、右侧分析面板展示和结束演练。

## 2. 执行原则

1. 先定义会话状态机，再写聊天界面。
2. 左中右三栏的数据边界必须稳定。
3. 前端只消费 `start / turn / restart / end` 语义，不自行拼接业务逻辑。
4. 输入、消息流和右侧面板必须能处理异步失败与重试。
5. 场景切换和会话重启必须可预测。

## 3. 子任务拆解

### 子任务 1: 页面路由与会话状态骨架

**目标**
- 搭建陪练场页面路由和主状态
- 明确场景、消息、会话、右侧分析面板的数据边界

**建议文件**
- 修改 `apps/web/app/(main)/dojo/page.tsx`
- 新增 `apps/web/components/dojo/DojoPage.tsx`
- 新增 `apps/web/store/dojo-store.ts`
- 新增 `apps/web/tests/frontend/dojo-page.test.tsx`

**交付物**
- 页面骨架
- 会话状态
- 场景状态
- 优先复用 `MainHeader`、`PageShell`、`SidebarLayout`

**验收点**
- 页面可以稳定进入初始态、对话态、结束态

---

### 子任务 2: 左侧场景与技巧面板

**目标**

**建议文件**

- 新增 `apps/web/components/dojo/ContextCard.tsx`
- 新增 `apps/web/components/dojo/TipsCard.tsx`
- 新增 `apps/web/lib/frontend/scenario-client.ts`

**交付物**
- 场景切换组件
- 心理语境展示
- 技巧列表展示
- 信息卡片优先复用 `GlassCard`

**验收点**
- 三个场景顺序固定
- 场景切换后内容同步更新

---

- 新增 `apps/web/components/dojo/MessageBubble.tsx`

**验收点**
- 会话开始、续聊、重启的交互链路完整
- 发送中和失败态可识别

### 子任务 4: 右侧实时分析面板

**目标**

### 子任务 5: 结束演练与总结展示

**目标**

**建议文件**

**交付物**

**验收点**
- 会话结束后不再允许误发消息

---

### 子任务 6: 响应式与交互稳定性

**目标**
- 打通桌面三栏和移动端折叠布局
- 处理滚动、输入聚焦、长消息和低网速状态

**建议文件**
- 修改 `apps/web/components/dojo/*`
- 必要时补充辅助 hooks

**交付物**
- 移动端折叠侧边栏
- 长消息换行和滚动控制
- 键盘发送和禁用态处理

**验收点**
- 移动端可完成完整会话
- 长消息不会破坏布局

---

### 子任务 7: 测试与回归

**目标**
- 为陪练场建立稳定回归测试
- 锁定场景切换、消息流转、右侧面板和结束动作

**建议文件**
- 新增 `apps/web/tests/frontend/dojo-page.test.tsx`
- 必要时新增 `apps/web/tests/e2e/dojo.spec.ts`

**交付物**
- 场景切换测试
- 消息发送测试
- `restart` 行为测试
- `end` 行为测试

**验收点**
- 会话状态机变更时能及时发现回归

## 4. 推荐执行顺序

1. 子任务 1，先冻结页面状态模型。
2. 子任务 2，完成左侧场景面板。
3. 子任务 3，打通聊天主链路。
4. 子任务 4，接右侧分析面板。
5. 子任务 5，完成结束演练。
6. 子任务 6，补响应式和交互稳定性。
7. 子任务 7，补回归测试。

## 5. 逐项完成标准

- 左中右三栏都能独立工作且能联动。
- 会话流转稳定。
- 右侧分析字段与后端契约一致。
- 页面可在桌面和移动端完成主流程。
