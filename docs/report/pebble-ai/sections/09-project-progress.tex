\section{已完成能力面}

\subsection{前端交互层}

当前可运行的前端能力覆盖以下页面与交互面：

\begin{itemize}
  \item 首页：主视觉、功能入口、滚动触发动效与模块化信息卡片已联通。
  \item 读心翻译页：支持文本输入、解码触发、结构化结果展示与建议保存入口。
  \item 模拟陪练页：支持场景选择、回合对话、右侧实时反馈与会话结束总结。
  \item 急救呼吸页：支持 4-7-8 节奏、倒计时、暂停/重置与阶段同步提示。
  \item 关系管理与个人中心：支持关系对象创建、编辑、读取及当前关系选择持久化。
  \item 设计系统组件：玻璃卡片、按钮、状态胶囊、页面壳与呼吸动效组件已投入页面复用。
\end{itemize}

前端状态管理与设计系统的具体实现细节如下：

\begin{itemize}
  \item 四个 Zustand store（翻译、陪练、关系、用户中心）通过显式状态读取调用实现跨 store 通信。翻译 store 在解码时通过全局用户中心 store 的读取接口获取当前关系标识；用户中心 store 使用 persist 中间件将当前关系标识持久化到 localStorage，页面刷新后通过 \texttt{loadSelectedRelation} 重新拉取详情。
  \item 设计令牌集中在 \texttt{lib/design-system/tokens.ts} 中定义，包含颜色（\texttt{pebbleColors}）、字体（\texttt{pebbleFonts}）、圆角（\texttt{pebbleRadii}）、阴影（\texttt{pebbleShadows}）与动效时长（\texttt{pebbleMotionDurations}）五组常量，并同时通过 CSS 变量注入 \texttt{globals.css}。
  \item 呼吸状态机提取为纯函数模块 \texttt{lib/breathing/breathing-machine.ts}，暴露 \texttt{BreathingPhase} 类型、\texttt{BREATHING\_CYCLE} 常量与 \texttt{nextPhase} 函数，与 React 完全解耦。
\end{itemize}

后端策略层已具备以下可观测能力：

\begin{itemize}
  \item PII 脱敏：解码路径在分析前执行敏感信息替换。
  \item 限流与超时：按 session/IP 执行请求频率控制，分析链路设置超时边界。
  \item 确定性降级：分析失败时回退启发式路径，保障主功能连续可用。
  \item 匿名会话：以 \texttt{guest\_session\_id} 支撑未登录用户的最小身份路径。
\end{itemize}

前端调用层已实现的 client 模块包括 \texttt{decode-client.ts}、\texttt{simulator-client.ts}、\texttt{relation-client.ts} 与 \texttt{practice-client.ts}，分别负责把对应功能域的 store 动作映射为统一 HTTP 请求。其中解码客户端设置 15 秒超时，练习客户端负责把解码或陪练结果写入练习条目。

数据库中有三个表使用 JSONB 存储结构化快照，其内部字段如下：

\begin{itemize}
  \item \texttt{practice\_entries.content\_jsonb}：包含 \texttt{originalText}（原始输入文本）、\texttt{analysis}（含 \texttt{attackType}、\texttt{scenario}、\texttt{subtext}、\texttt{emotionScore}、\texttt{neutralityScore}）与 \texttt{replyOptions} 数组（含 \texttt{id}、\texttt{label}、\texttt{content}、\texttt{tone}）。
  \item \texttt{simulation\_turns.analysis\_jsonb}：包含 \texttt{score}（情绪得分）、\texttt{label}（等级标签）与 \texttt{feedback}（即时反馈文本）。
  \item \texttt{simulation\_sessions.history\_snapshot}：包含 \texttt{totalTurns}（轮次总数）与 \texttt{averageScore}（平均得分）。
\end{itemize}

\section{阻塞、依赖与风险}

当前阻塞与风险主要集中在三类依赖：

\begin{itemize}
  \item 验证深度依赖：后端关键路径自动化测试仍需补齐，影响发布信心上限。
  \item 文档一致性依赖：OpenAPI 规范未与接口演进保持同频，影响协作效率。
  \item 运行时沉淀依赖：呼吸与活跃度数据链尚未闭环，限制长期洞察能力建设。
\end{itemize}
