## 上下文

### 背景
Pebble AI 模拟陪练场是核心练习功能，允许用户在安全环境中练习灰岩应对技巧。目前已有首页、翻译器、呼吸页实现，陪练场是最后一个核心功能模块。

### 当前状态
- **设计系统**: TB-005 已完成，定义了鹅卵石视觉语言、玻璃拟态、配色系统
- **前端基础**: 已存在 `/apps/web/components/dojo/` 目录，有基础组件占位
- **后端架构**: BFF 模式已建立，已有 `/api/decode` 等接口参考
- **设计稿**: `pebble_dojo.html` 第二版为唯一视觉真相源

### 约束
1. **前端优先**: 第二版 HTML 是视觉和交互真相源，后端必须适配
2. **rightPanel 契约**: 必须包含 analysisScore、analysisLabel、analysisSummary、instantFeedback、attentionPoint
3. **会话语义**: 必须实现稳定的 start/turn/restart/end 四种状态流转
4. **TDD 强制**: 所有代码必须先有测试，测试驱动实现
5. **TypeScript 严格**: 禁止 any，优先使用高级类型

## 目标 / 非目标

### 目标
- 实现三栏固定布局（桌面）/折叠侧边栏（移动端）
- 完成场景选择、聊天对话、实时情绪分析三大功能模块
- 实现 start/turn/restart/end 完整会话生命周期
- 情绪得分圆环 0-100 分，四级颜色动画过渡
- 响应式适配桌面端（≥1024px）和移动端（<768px）
- 所有外部调用实现超时、限流、fallback

### 非目标
- 语音输入的后端实现（仅 UI 占位）
- 用户历史会话的持久化存储
- 多语言支持
- 实时协作/多人陪练

## 决策

### 1. 状态管理: Zustand + Immer
**决策**: 使用 Zustand 管理会话状态，Immer 处理不可变更新

**理由**:
- 会话状态复杂（scenario + messages + rightPanel + sessionId），需要集中管理
- 避免 props drilling，三栏组件都需要访问状态
- Immer 简化嵌套状态更新逻辑

**替代方案**: Context + useReducer（拒绝：样板代码过多）；Redux Toolkit（拒绝：过重，非必要）

### 2. 后端 API 语义: 单端点多动作
**决策**: `POST /api/simulator` 统一处理 start/turn/restart，通过请求体字段区分

**理由**:
- 保持 REST 简洁，避免过多端点
- 三种操作共享相同的请求/响应结构
- 前端调用逻辑统一，便于封装 client

**替代方案**: 三个独立端点 `/start`, `/turn`, `/restart`（拒绝：冗余，语义重复）

### 3. 消息气泡圆角: CSS 硬编码
**决策**: 消息气泡圆角使用固定 CSS 值，不从设计系统动态计算

**理由**:
- 任务书明确指定具体值：AI `0.5rem 2rem 2.5rem 2rem`，用户 `2rem 0.5rem 2rem 2.5rem`
- 动态计算会增加复杂度，无实际收益
- Tailwind 不支持运行时动态圆角

### 4. 情绪得分动画: Framer Motion
**决策**: 使用 Framer Motion 实现圆环分数过渡动画

**理由**:
- 项目已引入 Framer Motion 11，保持一致性
- 支持 spring 动画和 layoutId，交互流畅
- 与 React 集成良好，声明式 API

**替代方案**: CSS transition（拒绝：不支持 spring 物理效果）；SVG animate（拒绝：过于底层）

### 5. 移动端侧边栏: 抽屉式折叠
**决策**: 移动端左右侧边栏采用抽屉式折叠，底部工具栏常驻

**理由**:
- 聊天区是核心交互，需要最大空间
- 抽屉模式符合移动端习惯（类似微信聊天设置）
- 底部工具栏常驻保证"重启"、"结束演练"始终可访问

**替代方案**: 三栏堆叠（拒绝：聊天区空间被严重挤压）；Tab 切换（拒绝：打断会话连续性）

### 6. AI fallback: 预设回复池
**决策**: AI 服务异常时返回预设回复池中的随机友好回复

**理由**:
- 确定性 fallback，保证用户体验一致性
- 避免暴露内部错误信息
- 预设回复经过设计，符合灰岩陪练场景

### 7. 文件组织: 按功能分目录
**决策**: 组件按功能划分为 dojo/ 子目录，不采用扁平结构

**理由**:
- ScenarioPanel、ChatArea、CoachingPanel 三个主要区块职责清晰
- 便于团队协作，减少冲突
- 符合 TB-003 执行清单的子任务划分

## 风险 / 权衡

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI 响应延迟 > 5s | 用户体验差，感知卡顿 | 3s 显示打字指示器，5s 超时 fallback |
| 情绪评分不准确 | 用户不信任系统建议 | 后端使用结构化输出 + few-shot，定期人工校准 |
| 移动端输入被键盘遮挡 | 无法看到最新消息 | 监听 visualViewport，自动滚动到底部 |
| 会话状态意外丢失 | 用户需要重新开始 | Zustand persist 中间件，定期本地存储 |
| 并发会话导致数据错乱 | 分析结果对应错误消息 | sessionId 绑定到请求/响应，前端严格校验 |
| 长消息破坏布局 | 气泡溢出、滚动异常 | max-width 80%，word-break break-word |
