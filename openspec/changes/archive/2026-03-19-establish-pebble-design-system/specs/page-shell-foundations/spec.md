## ADDED Requirements

### 需求: 页面壳必须为四个主页面提供统一结构
系统必须提供页面壳基础能力，以支持首页、翻译器、陪练场和呼吸页的主导航、内容容器、分栏结构和底部区域，禁止每个页面自行定义完全不同的主结构。

#### 场景: 页面复用统一主导航
- **当** 首页、翻译器、陪练场和呼吸页渲染顶部导航
- **那么** 它们必须能够复用统一导航壳，并保持一致的品牌展示、主入口和激活态规则

#### 场景: 页面复用统一内容容器
- **当** 页面渲染主体内容
- **那么** 系统必须提供统一的容器宽度、边距和垂直节奏规则

### 需求: 页面壳必须定义稳定的响应式布局规则
系统必须定义桌面端和平板端、移动端的主布局规则，至少覆盖首页首屏、翻译器三栏布局、陪练场三栏布局和呼吸页居中布局的响应式退化行为。

#### 场景: 翻译器在移动端堆叠
- **当** 屏幕宽度进入移动端断点
- **那么** 翻译器的输入区、解码按钮和结果区必须按稳定顺序堆叠，而不是维持桌面端三栏结构

#### 场景: 陪练场在移动端折叠侧栏
- **当** 屏幕宽度进入移动端断点
- **那么** 陪练场必须允许侧栏折叠或退化，而保证聊天主流程仍可完成

### 需求: 页面壳必须具备可访问性和关键状态约束
系统必须在页面壳层定义标题语义、键盘可达性、焦点可见性和关键区域可识别性，禁止页面通过纯视觉结构替代语义和交互反馈。

#### 场景: 键盘可达关键导航
- **当** 用户仅通过键盘访问页面
- **那么** 系统必须允许用户进入主导航、关键按钮和输入区域，并看到清晰焦点反馈

#### 场景: 页面标题层级稳定
- **当** 页面渲染主标题和区块标题
- **那么** 系统必须保证标题语义层级稳定，便于辅助技术识别页面结构

### 需求: 页面壳必须支撑设计系统测试回归
系统必须允许对页面壳进行渲染、断点和关键交互回归测试，确保后续页面实现不会偏离共享结构。

#### 场景: 页面壳测试验证主要布局
- **当** 测试渲染页面壳和主布局容器
- **那么** 测试必须能够验证主导航、内容容器和断点退化行为存在且稳定

#### 场景: 页面壳升级不破坏现有页面入口
- **当** 页面壳实现发生调整
- **那么** 回归测试必须能够发现导航入口、主要容器或关键布局是否被破坏
