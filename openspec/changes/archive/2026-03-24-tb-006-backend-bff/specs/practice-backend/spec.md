## ADDED Requirements

### 需求:系统必须提供practice条目保存接口
用户可以将读心翻译器或模拟陪练场的有价值内容保存到practice（练习本）。

#### 场景:从翻译器保存
- **当** 用户点击"存入练习本"按钮
- **那么** 系统保存原始文本、分析结果、三条回复建议
- **并且** 默认将方案A设为primaryReply

#### 场景:从陪练场保存
- **当** 用户在模拟陪练场选择保存某轮对话
- **那么** 系统保存该轮对话内容和分析摘要
- **并且** primaryReply由用户选定

### 需求:系统必须支持practice条目查询
用户必须能够查询自己的practice条目列表，支持分页和基本筛选。

#### 场景:获取列表
- **当** 用户打开练习本页面
- **那么** 系统返回该用户的practice条目列表
- **并且** 支持按收藏状态、来源类型筛选

#### 场景:获取详情
- **当** 用户点击某条practice条目
- **那么** 系统返回该条目的完整内容

### 需求:系统必须支持practice条目更新
用户必须能够更新practice条目的元数据，如收藏状态、归档状态。

#### 场景:收藏条目
- **当** 用户点击收藏按钮
- **那么** 系统将该条目标记为已收藏

#### 场景:归档条目
- **当** 用户归档某条目
- **那么** 系统将该条目标记为已归档
- **并且** 默认列表查询不再返回已归档条目

### 需求:系统必须支持practice条目删除
用户必须能够永久删除practice条目。

#### 场景:删除条目
- **当** 用户确认删除某条目
- **那么** 系统从数据库中硬删除该记录
- **并且** 返回删除成功确认

### 需求:practice条目必须使用统一命名
系统所有代码和接口中，必须使用 `practice` 作为命名，禁止使用 `practice-book` 或其他变体。

#### 场景:API路径
- **当** 开发者调用practice相关API
- **那么** 路径为 `/api/practice`，而非 `/api/practice-book`

#### 场景:数据库表名
- **当** 查看数据库表结构
- **那么** 表名为 `practice_entries`，而非 `practice_book_entries`
