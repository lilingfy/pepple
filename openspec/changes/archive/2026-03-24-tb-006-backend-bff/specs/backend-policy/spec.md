## ADDED Requirements

### 需求:所有文本输入必须经过PII脱敏
系统在将用户输入发送到LLM或存入数据库前，必须移除或替换个人身份信息（PII），包括电话号码、邮箱、身份证号、姓名。

#### 场景:解码请求脱敏
- **当** 用户提交读心翻译器分析请求
- **那么** 系统在调用LLM前过滤所有PII
- **并且** 返回的分析结果不包含原始PII

#### 场景:陪练场对话脱敏
- **当** 用户在模拟陪练场发送消息
- **那么** 系统在存储对话记录前过滤PII

### 需求:API必须实现统一错误响应格式
所有后端错误必须返回统一的错误体结构，包含 `code`、`message`、`details` 字段。

#### 场景:LLM服务不可用
- **当** LLM提供商返回错误或超时
- **那么** 系统返回fallback结果
- **并且** 记录错误日志但不暴露内部细节给前端

#### 场景:请求参数无效
- **当** 请求参数未通过校验
- **那么** 返回400状态码和结构化错误信息
- **并且** 指明具体哪个字段校验失败

### 需求:敏感操作必须有限流保护
系统必须对LLM调用和敏感操作实施限流，防止滥用。

#### 场景:解码限流
- **当** 单个session在1分钟内提交超过5次解码请求
- **那么** 返回429状态码，提示用户稍后再试

### 需求:LLM调用必须有超时保护
所有LLM调用必须设置超时，避免长时间挂起影响用户体验。

#### 场景:智谱AI超时
- **当** 智谱AI响应时间超过10秒
- **那么** 自动切换到mock分析结果
- **并且** 记录超时日志
