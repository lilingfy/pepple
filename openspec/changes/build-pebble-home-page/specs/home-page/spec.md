## ADDED Requirements

### 需求: 首页必须提供统一的品牌入口结构
首页必须在 `/` 路由渲染统一的品牌入口结构，包含导航栏、Hero 区、统计区、功能预览区和页脚，并且这些区块的顺序必须稳定。

#### 场景: 首页首次加载渲染完整结构
- **当** 用户访问 `/`
- **那么** 系统必须展示导航栏、Hero、统计区、功能预览区和页脚

#### 场景: 首页区块顺序保持一致
- **当** 页面在不同屏幕尺寸下渲染
- **那么** 主要区块的顺序必须保持稳定，不得打乱品牌叙事

### 需求: 首页必须复用共享页面壳和设计系统
首页必须复用 `MainHeader`、`PageShell` 和 `TB-005` 已交付的基础组件，禁止为首页另起一套平行布局或视觉体系。

#### 场景: 首页渲染共享导航壳
- **当** 首页展示顶部导航
- **那么** 导航必须与其他主页面共享同一壳层规则

#### 场景: 首页渲染共享视觉组件
- **当** 首页展示按钮、卡片或状态标签
- **那么** 系统必须使用共享设计系统组件输出一致的视觉语言

### 需求: 首页必须传达产品价值并引导进入核心功能
首页必须明确传达“情绪防御助手”的核心理念，并提供到读心翻译器、模拟陪练场和急救呼吸的清晰入口。

#### 场景: Hero 传达核心价值
- **当** 用户浏览首屏
- **那么** 首页必须展示产品价值主张和主要行动按钮

#### 场景: 功能卡片引导跳转
- **当** 用户点击核心功能预览卡片
- **那么** 系统必须将用户引导到对应路由 `/translator`、`/dojo` 或 `/breathing`

### 需求: 首页必须展示稳定的品牌可信度信息
首页必须提供统计区或等价的可信度展示区，用于展示品牌数据、产品结果或安全感信息，并且该信息必须在视觉上稳定可识别。

#### 场景: 首页展示可信度数据
- **当** 首页渲染统计区
- **那么** 系统必须展示至少四项可信度信息

#### 场景: 可信度信息可被阅读
- **当** 用户在桌面端或移动端浏览统计区
- **那么** 数字、描述和层次关系必须清晰可读

### 需求: 首页必须满足响应式和可访问性约束
首页必须在桌面端、平板端和移动端保持可用，并且必须支持键盘导航、语义标题和清晰焦点状态。

#### 场景: 移动端首页可读
- **当** 屏幕进入移动端断点
- **那么** 首页必须保留内容可读性，不能出现横向溢出或结构错乱

#### 场景: 键盘用户可完成主要操作
- **当** 用户只使用键盘访问首页
- **那么** 用户必须可以进入导航、CTA 和功能入口，并看到清晰焦点反馈

### 需求: 首页必须具备稳定的回归测试边界
首页必须支持渲染、跳转、主文案和无障碍回归测试，确保后续样式拆分和组件重构不会破坏首页契约。

#### 场景: 首页渲染测试可通过
- **当** 测试渲染首页
- **那么** 测试必须能验证关键区块存在

#### 场景: 首页跳转测试可通过
- **当** 测试点击首页核心入口
- **那么** 测试必须验证路由跳转到正确页面
