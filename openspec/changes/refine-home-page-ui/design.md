## 上下文

首页基础布局已在 `build-pebble-home-page` 变更中完成并归档，但对比设计稿 `pebble_home.html` 存在以下视觉细节缺口：

1. **Logo**：当前为正圆形，设计稿为异形鹅卵石
2. **导航**：缺少当前页脉冲点指示器
3. **Hero**：缺少底部滚动指示器，CTA 按钮与设计稿不符
4. **统计区**：数字前缺少脉冲绿点和发光阴影
5. **功能预览**：简化为卡片列表，设计稿为三段式详情展示（Demo UI + 场景卡片 + 呼吸动画）
6. **页脚**：版权信息和链接结构不完整
7. **滚动动画**：全局缺少 IntersectionObserver 驱动的渐显效果

本变更是对首页的视觉完善，不改动路由结构或页面骨架，仅补充缺失的 UI 细节和交互动效。

## 目标 / 非目标

**目标：**
- 补齐首页与设计稿的视觉差异，确保品牌一致性
- 实现滚动渐显动画，提升页面浏览体验
- 完成功能预览区的 Demo UI，增强产品展示力度
- 保持代码模块化，新增组件遵循 TDD 开发流程

**非目标：**
- 不改动首页整体布局结构（导航/Hero/统计/功能/页脚的顺序）
- 不新增后端 API 或数据持久化逻辑
- 不修改设计系统基础组件（Button、Card 等）
- 不改变已有的响应式断点策略

## 决策

### 1. 滚动动画使用 IntersectionObserver + CSS 类切换，而非 Framer Motion

**理由**：滚动动画是一次性触发、无需复杂编排的渐显效果，IntersectionObserver 足够满足需求，且无需引入额外的 JS 动画库运行时开销。

**备选方案**：Framer Motion 的 `whileInView`。缺点是对于简单的透明度/位移动画过于重量级。

### 2. Demo UI 组件使用纯静态数据，不调用真实 API

**理由**：功能预览区的目的是展示产品能力，而非真实交互。使用静态数据可以确保演示内容的稳定性和即时渲染，避免网络延迟影响首屏体验。

**备选方案**：调用 `/api/decode` 真实接口。缺点是增加不必要的后端负载，且演示内容不可控。

### 3. 呼吸动画复用 `breathing/page.tsx` 的核心 CSS 动画逻辑

**理由**：保持与完整功能页一致的动画时序和视觉风格，确保品牌一致性。提取为可复用的 CSS 类，供首页和呼吸页共用。

**备选方案**：重新实现一套动画。缺点是维护成本高，容易产生视觉差异。

### 4. 组件拆分粒度：每个视觉区块独立组件

**理由**：`TranslatorDemo`、`DojoScenarios`、`BreathingOrb` 作为独立组件，便于单独测试和维护。首页仅负责编排，不承担具体实现。

**备选方案**：所有内容写在 `FeatureSection.tsx`。缺点是文件过大，难以测试。

### 5. 减少动画偏好支持 `prefers-reduced-motion`

**理由**：确保可访问性合规。滚动动画和呼吸动画在启用减少动画偏好时，应退化为静态展示或简化效果。

## 风险 / 权衡

- **[滚动动画在快速滚动时可能触发频繁]** → 使用 `threshold: 0.15` 和 `rootMargin` 优化触发时机，并设置 `will-change` 提示浏览器优化
- **[Demo UI 与真实功能页视觉不同步]** → Demo UI 仅展示核心信息架构，不追求 1:1 复刻真实页面，在组件文档中明确标注此为演示专用
- **[异形圆角在不同浏览器渲染差异]** → 使用 `border-radius` 百分比值，在主要浏览器（Chrome/Firefox/Safari）中测试通过
- **[新增组件增加包体积]** → 所有新增组件均为轻量级展示组件，无额外依赖，预计增加体积 < 5KB gzip

## 迁移计划

1. 创建 `ScrollReveal` 包装组件，为首页各区块添加滚动动画
2. 更新 `Navigation`、`HeroSection`、`StatsSection`、`Footer` 组件
3. 实现 `TranslatorDemo`、`DojoScenarios`、`BreathingOrb` 功能预览组件
4. 更新 `FeatureSection` 使用新组件替换原有卡片列表
5. 回归测试：验证所有动画在 `prefers-reduced-motion: reduce` 下正确退化
6. 视觉回归测试：与设计稿对比关键像素
