# Capability: pebble-design-system

## Purpose

定义 Pebble 共享设计系统的基础规范，约束设计令牌、基础组件、关键状态和组件纯度，作为首页、翻译器、陪练场和呼吸页的统一视觉与交互基座。

## Requirements

### 需求: Pebble 设计令牌必须统一定义
系统必须提供统一的 Pebble 设计令牌，至少覆盖颜色、字体、阴影、圆角、间距和基础动画时长，禁止页面模块各自定义不一致的同类视觉常量。

#### 场景: 页面复用统一颜色和圆角
- **当** 首页、翻译器、陪练场和呼吸页使用主色、强调色和鹅卵石圆角
- **那么** 它们必须从同一套设计令牌中读取，而不是在页面内重复硬编码

#### 场景: 设计令牌支持测试验证
- **当** 测试读取设计令牌导出
- **那么** 系统必须能够验证关键颜色、字体和圆角常量存在且名称稳定

### 需求: Pebble 基础组件必须复用统一视觉语言
系统必须提供基础组件层，至少包括按钮、玻璃卡片、输入壳、状态标签和分区标题，并且这些组件必须复用统一设计令牌。

#### 场景: 页面使用统一按钮组件
- **当** 页面需要主按钮或次按钮
- **那么** 系统必须允许页面通过统一按钮组件渲染，而不是重新实现不同的按钮视觉和交互

#### 场景: 页面使用统一玻璃卡片组件
- **当** 页面需要展示统计信息、分析结果或辅助信息
- **那么** 系统必须允许页面通过统一玻璃卡片组件获得一致的玻璃拟态背景、阴影和边框规则

### 需求: 基础组件必须覆盖关键状态
系统中的基础组件必须定义并支持关键视觉和交互状态，至少包括默认态、悬停态、禁用态、加载态中的适用子集。

#### 场景: 按钮组件处理加载与禁用
- **当** 页面将按钮置为加载或禁用
- **那么** 组件必须渲染稳定状态，并禁止误触发主交互

#### 场景: 输入壳处理聚焦状态
- **当** 用户聚焦输入组件
- **那么** 组件必须显示统一的高亮和边界反馈，而不是由页面单独实现

### 需求: 设计系统组件必须可测试且无业务副作用
系统中的设计系统组件必须通过 props 接收数据和状态，禁止直接发起网络请求、直接读取业务 store 或耦合页面私有逻辑。

#### 场景: 页面传入数据驱动展示
- **当** 页面将文案、图标或状态传入设计系统组件
- **那么** 组件必须只根据输入 props 渲染结果，而不依赖页面外的业务副作用

#### 场景: 组件测试独立运行
- **当** 测试独立渲染设计系统组件
- **那么** 测试必须能够在不模拟业务接口的情况下完成组件验证
